# 의료기기 수출 거래서류 검토

사이트: https://lmo052034.github.io/med-export-helper/

해외영업 담당자가 현지 파트너에게 견적을 보내기 전에 **거래조건을 한 곳에 정리하고, 견적서·상업송장·메일의 누락과 불일치를 검토**하는 웹앱입니다. 팀(에프킬라)이 제안하는 도구이며, 특정 회사가 이런 문제를 겪고 있다고 주장하지 않습니다. 로그인과 유료 API 없이 브라우저에서 동작합니다 (React + Tailwind + shadcn/ui, GitHub Pages).

> 거래조건을 입력하면 견적서와 인보이스가 함께 갱신되고, 중량·서명 누락과 조건 불일치를 찾아 수정할 수 있습니다.

## 메뉴

| 메뉴 | 주소 | 하는 일 |
|---|---|---|
| 수출 제안 | `#/` | 제품 이해 → 국가 선정 근거 → 거래 구조 → 조건 바꿔보기 → 서류로 이어지는 제안 소개 (내용은 콘텐츠 팩) |
| 가격·수익성 | `#/price?tab=deal`, `hospital`, `cash` | 거래 가격(수출가, 환율, 비용, 현지 판매가, 파트너 손익), 병원 운영(공헌액, 월 운영 현금잉여, 손익분기, 단순 회수, 그래프, 시나리오), 결제 흐름(일시 필요 자금). 기준안과 비교·되돌리기 |
| 병원 도입 검토 | `#/hospital` | 파트너 영업 담당자가 병원 앞에서 쓰는 화면. 병원의 시술가, 환자 수, 결제 조건(일시불, 파트너 분할, 할부·리스)으로 손익분기, 월 손익, 누적 회수, 민감도를 바로 계산. 결과 패널은 한국어/인도네시아어 전환. 인도네시아어 제안서와 원장 질문 답변(계산값 기반, AI 키를 넣으면 Claude가 다듬음). 병원별 검토를 이 브라우저에 여러 건 저장 |
| 거래서류 | `#/deal`, `#/review`, `#/docs` | 거래조건 입력, 검토 결과, 서류 미리보기(수출 견적서, 상업송장 초안, 메일 초안, 현지 견적). 인쇄·PDF에는 서류만, 초안·모의 표시는 유지 |
| 근거자료 | `#/evidence` | 값의 출처 구분(회사 자료, 공개자료, 팀 설정, 모의, 사용자 입력), 계산식, 바뀐 값 기록 |

## 콘텐츠 팩

첫 화면 문구, 제품 사진, 대표 모의 거래는 '콘텐츠 팩'에서 읽습니다. 이 저장소에는 특정 회사 정보가 없는 예시 팩(`src/pack-default/`)만 있습니다.

```bash
npm run dev                                  # 예시 팩
PACK_DIR=/경로/내-팩 npm run dev              # 다른 팩 (index.js에서 PACK, sampleDeal 내보내기)
PACK_DIR=/경로/내-팩 npx vite build --outDir 다른-폴더
```

실제 기업의 비공개 자료, 연락처, 가격표가 담긴 팩은 공개 저장소에 넣지 마세요.

## 계산 (src/lib/deal/econ.js, 모든 화면이 같은 함수 사용)

- 회당 공헌액 = 회당 실제 수납액 − 회당 변동비
- 월 운영 현금잉여 = 월 유료 시술 × 공헌액 − 월 추가 고정비 (장비 상각비 제외)
- 운영 손익분기 = 올림(고정비 ÷ 공헌액), 공헌액 0 이하이면 산출 안 함
- 단순 회수 = 초기 도입비 ÷ 월 현금잉여, 잉여 0 이하이면 산출 안 함
- 파트너 거래 손익(세전) = 현지 공급가(부가세 제외) − 수출 대금 × 환율 − 포함한 비용 − 관세(CIF 기준). 수입 부가세, PPh 22는 결제 흐름에만

수출 거래(제조사 → 파트너, 예: USD)와 현지 판매(파트너 → 병원, 예: IDR)는 당사자·통화·가격·결제를 따로 가집니다. 현지 가격은 수출가에 환율을 곱해 만들지 않고, 파트너가 준 값이나 팀이 정한 모의 값만 씁니다. 원가 자료가 없으므로 제조사 이익은 계산하지 않습니다.

## 병원 도입 검토 계산 (src/lib/review/calc.js)

- 회당 순수납 = 시술가 × (1 − 코스 할인) × (1 − 결제 차감), 회당 공헌 = 순수납 − (의사 수당 + 소모품 + 전기료 + 핸드피스 교체비)
- 전기료 = VA ÷ 1000 × 사용 분 ÷ 60 × PLN 요금, 핸드피스 교체비 = 가격 ÷ 수명(발) × 회당 발수 (빈칸이면 결과에서 빠졌다고 표시)
- 머리 손익분기: 할부면 올림((고정비 + 월 납입금) ÷ 공헌), 일시불이면 올림((고정비 + 도입가 ÷ 배분 개월) ÷ 공헌). 운영비만의 손익분기도 함께 표시
- 금융: 실효 금리는 원리금 균등, 플랫 금리는 원금 × (1 + 연이율 × 기간) ÷ 개월, 플랫은 실효 금리로 역산해 표시
- 누적 현금 = −(계약 때 낸 돈) + 매달(시술 × 공헌 − 고정비 − 납입금), 초기 증가 기간은 선형 가정
- BPJS 환자는 INA-CBG 묶음 수가라 세지 않음. 모든 값은 세전, 수익 보장 아님
- 장비별 기본값과 출처는 콘텐츠 팩의 `PACK.review`(defaults, sources, benchmarks, facts, faq)에서 읽고, 공통 근거(BI 기준금리, OJK 평균 대출금리, PLN 요금, PP 49/2022, Kepmenkes 1366/2024)는 `src/lib/review/model.js`에 있음
- AI 키는 이 브라우저에만 저장(선택)하고 Claude API(claude-opus-5-5)를 브라우저에서 직접 호출. 키가 없으면 계산값으로 만든 기본 문안을 씀

## 검토 범위

규칙과 계산식으로만 확인합니다 (AI 판단 아님). 법적 적합성, 통관 승인, 판매 가능 여부는 판단하지 않고, 이 도구 밖의 문서와 대조하지 않습니다.

- 단계(견적 / 출하·인보이스)별 필수 입력 누락
- 수량 × 단가, 합계, 별도 비용 포함 여부, 결제 회차 합계(비율 반올림 차이는 마지막 회차), 통화별 소수 자릿수
- 빈칸과 0 구분, 음수, 숫자가 아닌 값, 없는 날짜
- 중량: 빈칸, 총중량 < 순중량, 단위 불일치, 포장 1개당 / 전체 구분 (포장 수와 제품 수는 달라도 됨)
- 가격 없는 추가 구성품 → "추가 구성의 가격 확인 필요" (가격을 만들지 않음)
- 인보이스 조건을 견적서와 다르게 쓰면 사유와 차이 표시, 같으면 "기준정보로 동기화됨"
- Incoterms 2020 해상 전용 조건과 운송 방식, EXW 수출통관 담당 (근거와 함께 '확인 필요'로만 표시)
- 검토 완료 표시 후 핵심 조건이 바뀌면 다시 확인 요청
- 근거자료는 "출처 있음"과 "내용 확인함"을 나눠 표시

## 데이터와 저장

- 입력값은 이 브라우저 localStorage(`mdk:deals`)에만 저장됩니다. 서버로 보내지 않습니다. 다른 기기로 옮기려면 '거래 → 파일로 내보내기'.
- 이전 버전 저장값(`mdk:deal`, `mdk:log`)은 처음 열 때 새 거래와 근거자료로 옮기고, 원본 키는 지우지 않습니다. 읽을 수 없는 저장값은 `mdk:deals.backup-…`로 백업합니다.
- 저장소에는 회사명이 없는 **모의 거래**만 들어 있습니다. 실제 회사 사례는 JSON 파일로 따로 보관하고 '거래 → 사례 파일 불러오기'로 엽니다. 불러온 사례는 항상 새 거래로 추가되어 기존 거래를 덮어쓰지 않습니다.
- 이전 메뉴 주소(`#/readiness`, `#/programs`, `#/market`, `#/compliance`, `#/promo`, `#/buyer`, `#/log`, `#/cases`)는 거래조건 화면으로 연결됩니다.

## 실행

- 로컬: `npm install` → `npm run dev` → http://localhost:5173/
- 빌드: `npm run build` (main에 push하면 Actions가 빌드·배포)
- 단위 테스트: `npm run test:unit` (계산·검사·이전 데이터)
- 브라우저 테스트: `npx playwright install chromium` 후 `npm test` (시연 흐름, 저장 복원, 이전 데이터, 옛 주소, 모바일, 인쇄, 이름표)

## 시연 순서

1. 처음 열면 모의 거래가 열립니다 (또는 '거래 → 사례 파일 불러오기').
2. 제품·가격에서 구성이나 수량을 바꿉니다 → 오른쪽 견적서·인보이스 금액이 함께 바뀝니다.
3. 검토 결과에서 총중량·발신자 서명 누락을 확인하고 '입력란으로 이동'.
4. 값을 넣으면 해당 항목이 사라집니다.
5. 서류 미리보기 → 전체 인쇄·PDF.

## 코드 위치

- `src/lib/deal/`: 거래 구조(model), 금액 계산(money, calc), 검토 규칙(checks), 저장·이전(storage)
- `src/components/deal/`: 화면 틀, 입력칸, 근거 패널, 서류
- `src/pages/`: 거래조건, 검토 결과, 서류 미리보기
- 지원사업 공고 수집기(`scripts/collect-notices.mjs`, `.github/workflows/notices.yml`)는 그대로 돌지만, 이번 개편에서 화면에서는 뺐습니다.
